# v2.2.0 书签检索与缓存刷新验证

基于贡献者 @valuex 的 PR #2（`f7bf535`）补充旧映射清理，原始提交和作者信息保留。

环境：Windows 11 家庭中文版 10.0.22621 x64、MSVC v143 Release x64、静态 CRT、20 个逻辑处理器。

## 修复与自动回归

- 每次书签查询开始前清理该关键词的旧映射，读取失败或超时也不会继续保留旧动作。
- 新结果替换旧列表，空结果同时清理原始输入行和已显示书签的映射。
- 仅清理对应关键词，保留浏览器历史、蓝牙与其他关键词映射。
- 新增 6 项回归检查，覆盖非空到空、关键词大小写、旧书签行失效、不同查询替换、来源 Profile 保留及其他模块隔离。
- Release x64 三工程编译通过；核心测试 142 项通过，`SUMMARY failures=0`。5000 条合成书签全匹配的适配器单次查询为 43.101 ms。

## 隔离宿主资源测试

使用同一 Release EXE 的独立测试目录，两个浏览器、四个 Profile，每个 Profile 5000 条书签，另加两条 UI 验收用书签，总计 20002 条。全部为合成数据，不改动真实浏览器书签。对实际 loopback 建议接口连续执行 30 次请求，轮换空查询、全匹配查询、无匹配查询，并验证返回数量。

| 指标 | 实测 |
|---|---:|
| 查询前私有工作集 | 1,839,104 B / 1.75 MiB |
| 查询期间采样峰值私有工作集 | 10,919,936 B / 10.41 MiB |
| 查询结束 3 秒后私有工作集 | 3,293,184 B / 3.14 MiB |
| 30 次 HTTP 请求耗时范围 | 55.241–123.832 ms |
| 平均 HTTP 请求耗时 | 70.562 ms |
| 约 1 秒空闲期间进程 CPU 时间增量 | 0 ms |

私有工作集通过 `QueryWorkingSet` 统计非共享驻留页，请求执行期间以约 5 ms 间隔采样，测量本身也有开销。请求耗时包含调用和采样开销；表中是本机采样值，不是资源硬上限，也没有覆盖单文件接近 16 MiB 的全部极端情况。未使用强制修剪工作集。

## 验证边界

- 本轮验证了核心映射和真实 HTTP 建议接口，没有宣称完成真实 Listary 下拉的鼠标/键盘验收。
- 桌面自动化未能枚举插件的工具窗口，后台静默接入配置命令也被自动安全检查拦截，因此未改写本机 Listary 接入配置。
- 本机原安装的 INI 和 Listary Preferences 经哈希核对保持不变，原插件已恢复运行。
- 安装包通过编译、版本和文件校验，不代表本机已执行覆盖安装。
