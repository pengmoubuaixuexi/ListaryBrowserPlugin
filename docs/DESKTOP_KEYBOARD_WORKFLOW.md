# 键盘工作流与 Listary 外接扩展

## 当前分工

- **Listary**：统一的键盘入口、文件/应用搜索、命令和下拉结果界面，保持默认的双击 `Ctrl` 呼出方式。
- **BrowserHistoryLauncher**：只负责按需读取 Chrome/Edge 历史，把动态结果提供给 Listary，并用来源浏览器打开。本工具自身的 `Ctrl+Shift+Space` 保留为 Listary 不可用时的回退入口。
- **uTools**：承载需要表单、交互界面、剪贴板处理或多步骤操作的插件。
- **Snipaste**：截图、标注、贴图和临时视觉参考，不再叠加应用启动职责。

这样每个工具只做自己擅长的部分，避免多个全局快捷键和重复索引互相干扰。

## 给 Listary 增加能力的四种方式

### 1. 静态命令

适合“一次输入，一次启动”的动作，例如打开固定项目、调用 Windows Terminal、打开某个管理页面。直接使用 Listary 的自定义命令，把 `{query}` 作为参数传给目标程序。

### 2. 动态下拉结果

适合浏览器历史、窗口列表、最近项目等需要“输入后立即返回多项结果”的场景。沿用本项目已经验证的方式：

1. 本地原生进程仅监听 `127.0.0.1`，按需返回 Listary 建议结果；
2. 每条结果携带短期标识；
3. Enter 后通过当前用户 URL 协议交回本地进程；
4. 本地进程执行明确、有限的动作。

这种方式能在 Listary 自己的下拉列表里展示结果，但本地进程必须保持运行。

### 3. 对文件执行动作

适合“用某程序打开”“复制路径”“在终端中打开目录”等。使用 Listary 的自定义动作即可，无需再写常驻程序。

### 4. 富交互工作流

需要预览、表单、数据持久化、多步骤确认或复杂界面时，交给 uTools 插件。不要把复杂 UI 强行塞进 Listary 的建议列表。

## 推荐的下一批扩展

按实用性和风险排序：

1. **`w` 窗口切换器**：枚举当前可见窗口，在 Listary 下拉列表中选择，Enter 激活目标窗口。它最贴近“全键盘操作”，且不需要保存隐私数据。
2. **`p` 最近项目**：读取常用 IDE 的最近项目清单，显示项目名和路径，并用对应 IDE 打开。
3. **`ssh` 主机入口**：只读取 `%USERPROFILE%\.ssh\config` 中的 Host 别名，通过 Windows Terminal 启动；不读取或保存密码、私钥内容。
4. **固定工作区命令**：一条命令同时打开一个项目目录、终端和必要应用。若步骤复杂或需要条件判断，放到 uTools 插件中。

暂不建议优先做剪贴板历史、计算器、翻译、截图或通用服务管理：前三类通常会与现有工具重复，服务/进程控制则容易产生误操作。

## 项目边界

`REQUIREMENTS.md` 明确把本项目限定为浏览器历史启动器，因此不应把它扩成通用自动化框架。如果后续需要两个以上动态 Listary 数据源，建议另建独立的原生项目，例如 `ListaryBridge`，每个数据源作为一个小适配器；BrowserHistoryLauncher 继续保持单一职责。

## 快捷键建议

- Listary：双击 `Ctrl`
- BrowserHistoryLauncher 回退入口：`Ctrl+Shift+Space`
- Snipaste：保留当前截图键
- uTools：使用另一个不冲突的组合键

修改快捷键后，应分别验证普通桌面、资源管理器、浏览器和全屏应用，确认没有被其他软件抢占。
