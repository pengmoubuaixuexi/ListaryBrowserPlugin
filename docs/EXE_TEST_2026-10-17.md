## 本机状态与测试方式

- 已备份并替换运行程序：`E:\Program Files\ListaryBrowserPlugin\BrowserHistoryLauncher.exe`。
- 编译产物：`build\Release\BrowserHistoryLauncher.exe`；INI 与其放在同一目录。
- 旧 EXE、旧 INI、Listary 状态与 Preferences 备份：`build\installed-backup-20261017\`。
- 保留原有 `Ctrl+Shift+Space`、`g`、`e`、`q`、`ly` 和浏览器路径；仅在现有 INI 增加启用 `end` 的 `[applications]` 节。
- 新宿主已启动，`/health` 正常，`end` 建议接口实测可返回应用结果。
- 自动运行 `--configure-listary` 被执行策略拦截，**本机 Listary 仍未注册 end**。请右键插件托盘 → 配置 Listary → 保存并应用全部，完成这一步后再在 Listary 输入 `end`。既有 `g/e/q/ly` 保持可用。

手工验收：

1. 打开无重要内容的应用，在 Listary 输入 `end` 或 `end <窗口标题/EXE名>`。
2. 选择带“强制结束”和 PID 的具体下拉项。确认框默认“否”；先测试取消，再明确选择“是”。请先保存文件。
3. 用 `ly` 正常连接耳机，反馈出现时按 Enter，确认“确定”生效。当前测试只自动验证共享弹窗路径的真实前台/焦点与 Enter，不会擅自连接或切换用户的耳机。
4. 弹窗结束且没有继续输入后，宿主约 5 秒开始回收界面组件；查看后台内存是否回到低占用。

强制结束不是应用自己的退出，不保证保存/清理。仅处理一个选中进程，不处理同名所有实例或进程树；有些多进程软件可能留下后台组件。只枚举同用户/会话、普通可见窗口所属进程，最小化一般仍符合，只有托盘的程序不列出。排除系统关键/受保护进程、系统基础进程、Listary 和自身，不自动提权。
